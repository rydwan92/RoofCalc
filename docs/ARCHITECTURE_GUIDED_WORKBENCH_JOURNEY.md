# Guided Workbench UX / Project Journey

## Definition of Ready

1. User problem: first-time users need a clear start and a visible next task.
2. Owner: apps/web composes existing V47 readiness and V53 project journey.
3. Persistence: overview statuses and navigation are derived/transient only.
4. Schema: canonical schemas unchanged; one device-local MRU preference is documented in SCHEMA_REGISTRY. All V1 projects remain readable.
5. History: navigation/disclosures create no entry; existing edits retain transactions.
6. Quantity: only existing trusted results; no new source.
7. Procurement: no blank/allowance changes.
8. Catalogue: stored snapshots remain authoritative; no field changes.
9. Cost boundary: display existing cost readiness; no commerce enters geometry.
10. Offline: manual projects, guidance and recent local projects work offline.
11. Mobile: six wrapping stages, current stage, next action; exact values through existing Inspector/Creator at 390×844.
12. Research: no new geometry/overlap/connection semantics; not applicable.
13. Regression: pure journey lifecycle matrix, real browser start/navigation/overflow, existing fixture corpus unchanged.
14. Multi-structure: opaque IDs unchanged; no ID parsing.

## UX audit and implementation boundary

The repository already contains V31/V37 ProjectStartAssistant, V47 readiness,
V53 project-journey and direct readiness navigation. There is no separate
project-guidance file in current main. V53 has eight detailed stages behind the
readiness panel; V47 already supplies cost/document blockers. The existing
summary lacks costs/documents and dimensions; Materials has a text-only empty
state. Cost, covering and Document Hub already explain missing data with actions.
Inspector already collapses advanced parameters, but structure navigation does
not reveal them. These are presentation gaps, not missing domain engines.

The six-stage overview is a projection of the same detailed journey, with
complete / needs-action / not-started states. Covering includes its required
layers; materials includes configured roof-system decisions. Detailed stages
remain accessible. Completion means available workflow evidence, never structural
safety or proof that a document was exported. Optional, unstarted cost stays
not-started and does not block documentation. No saved completion flags.

Start reuses Creator and ProjectSession: new project, quick calculation, IFC
import; examples and direct expert editing remain under a disclosure. Recent
projects use a bounded device-local MRU list of opaque IDs, with update-order
fallback for older projects. All-project access expands the complete local list.
The root route presents start without initializing a project; Quick therefore
creates no record. Calculator deep links keep their fast direct entry.


## Guided navigation and result explanations

The compact strip and existing Materials summary consume the same `overview`
from `deriveProjectJourney`. Ready stages open their own task, not an incidental
informational action such as K1 planning. Unfinished groups open their actual
missing decision. Geometry and structure remain ahead of later optional advice.
Structure opens roof selection and the existing exact timber fields on both
layouts. No value has a second editable control.

The summary shows the roof dimensions/type/pitch, six statuses, three most
important warnings and the same recommended action. Its existing quantity
cards continue to explain physical vs geometric evidence. Materials' empty
state now links directly to structure; existing covering, cost and document
empty states remain in use. Changes to completion show a quiet timed inline
confirmation; creator geometry and structure transitions explain what comes
next. Mobile keeps the current stage and full next-action title visible above
the workspace, with no additional sticky overlay.
